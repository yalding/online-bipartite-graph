# Repository workflow

The user wants completed changes committed by default.

- At the end of each task that changes repository files, review the changes,
  run appropriate checks, and create a descriptive Git commit.
- Include research notes, plans, scripts, and relevant experiment artifacts
  produced by the task. Keep local dependency installations and caches ignored.
- Stage only task-related changes and preserve unrelated user work.
- Report the commit hash in the final response. If a commit is blocked, explain
  the concrete blocker.
- Commit locally; push only when the user requests it.
